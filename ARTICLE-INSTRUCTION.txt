# Инструкция проекта: новости WordPress

Единая инструкция. Всегда применяй.

Корень пакетов: `news/<slug>/`. В корень репозитория (`/<slug>/`) не класть.

---

## 1. Базовые запреты

- WordPress не трогай, пока пользователь явно не выбрал заливку: `zip_mcp` / `publish_mcp` / `find_upload` / «экспортировать ZIP» / «залить».
- Статус поста всегда `draft`, пока не сказали «опубликуй».
- Вопрос «Создать пост в черновик?» не использовать.
- Не base64 и не бинарник в MCP (`wp_upload_media` для тяжёлых JPEG сцен/thumbnail — нельзя).
- REST (`/wp-json/`, Application Password, curl) не используй. Только MCP-тулы.
- Не `zip_path` (это путь уже на сервере WP). Не localhost / 127.0.0.1 / частные IP.
- Не пиши, что пост на сайте, если MCP не вернул `post_id` / `success`.
- Ngrok URL в контент поста не писать (только аргумент загрузки).
- Ability `easy-mcp-zip-post-import/import-from-zip` можно и нужно: `zip_url` = `data.zipUrl` из public-files.

CLI (из корня проекта, где лежат `news/` и `public-files/`):

```bash
node public-files/index.js start news/<slug>
node public-files/index.js pack news/<slug>
node public-files/index.js stop
```

`start` печатает JSON: `data.zipUrl`, `data.files[].url`. Нет поля — ошибка, ссылку не выдумывай.
После заливки в `finally` всегда `stop`. Туннель не оставляй.

---

## 2. Как спрашивать после показа материала

После готового пакета — **только AskQuestion (кнопки)**. Длинный список команд текстом не дублируй.

Кнопка, где текст не по-русски (заголовок, overlay, концепт thumbnail): **оригинал — коротко по-русски**. Без русского дубля не спрашивать. В чате иностранную цитату сразу пояснять одной русской строкой.

На пикселях thumbnail русский **не** дублировать — только язык статьи.

Тайтлы для FB в кнопки не класть (только текстом в чате).

| id | label |
|---|---|
| prepare | Подготовить новость |
| update | Обновить новость |
| zip | Подготовить ZIP |
| export_zip | Экспортировать ZIP |
| zip_mcp | Залить ZIP в WordPress |
| publish_mcp | Залить в WordPress (MCP, картинки по одной) |
| fb_title | Тайтл для FB |
| search | Поиск актуальных новостей |
| find_sources | Поиск по источникам |
| social_check | Где запощено / не в ФБ |
| find_make | Найди и сделай |
| find_zip | Найди и сделай ZIP |
| find_upload | Найди и залей на сайт |
| translate | Перевести пост |
| link_translation | Связать перевод с постом |

Нет статьи — не показывай `update`, `zip`, `export_zip`, `zip_mcp`, `publish_mcp`.
Нет ZIP — `zip_mcp` / `export_zip` сначала пакуют.
Есть `post_id` — `update` в списке. Есть исходный пост в чате или id — покажи `translate` и `link_translation`.

«Сделай thumbnail / тамбнейл / обложку» при уже существующей статье = доделай **эту** папку и сюжет (тот же overlay-язык), не новый поиск.

## 3. Что делает каждая команда

### Подготовить новость (`prepare`)

Запиши на диск:

```
news/<slug>/post.json
news/<slug>/images/image1.jpg
news/<slug>/images/image2.jpg
news/<slug>/images/thumbnail.jpg   ← overlay уже на пикселях
```

Показ в чате без этих файлов не считается. ZIP не пакуй. WP не трогай.
Thumbnail: концепт спрашиваешь один раз. Как только человек выбрал вариант — в том же ответе GenerateImage и `images/thumbnail.jpg` (overlay + акцент). Не «принял» и не копия фото статьи. Подробно § 5.

Текст **3000–4000** слов. Перед показом строка `Слов: N`. Если N < 3000 — не сдавай и не спрашивай про заливку.

Категория, 5 тегов, язык, Yoast, excerpt (кликбейт FB).
Если по смыслу это новость, рубрика «новости» на языке статьи (как она уже называется на сайте: Nachrichten, Новости, News и т.п.) — **основная**, даже когда категорий несколько. В `category` / первым элементом `category_names` ставь её. Остальные темы — следом, не вместо неё. На сайте не плоди дубль, если такая рубрика уже есть (`wp_list_categories`). После заливки в Yoast primary = id этой рубрики (`_yoast_wpseo_primary_category`).
Сразу 3 `social_titles` в `post.json` (правила § Тайтл для FB).

Источники в **теле статьи и в конце** — см. § 4. Новость без ссылок внутри абзацев и без блока Quellen в `content` = подготовка не закончена.
Исключение только если человек **намеренно** сказал БЕЗ: «без источников», «придумай без ссылок», «вымысел», «фейк», «чистый вымысел». Тогда `source_urls: []`, ссылок в тексте нет.
Не сказали БЕЗ — это новость: реальные ссылки в абзацах у факта и тот же список в конце. Те же URL в `source_urls`. URL СМИ не выдумывай.

Покажи: пути, заголовок, `Слов: N`, содержание, блок источников (или явно «БЕЗ источников, по просьбе»), каждую картинку (`В тексте` / `На фото`), thumbnail (overlay + ширина + акцент), SEO, теги, язык, excerpt, `source_urls`, 3 social_titles.
Затем кнопки.

### Обновить новость (`update`)

Нужен `post_id`. Нет ID — спроси, новый пост не создавай. Не создавай второй пост.

Сначала прочитай живой пост с сайта (MCP, не REST):
- `wp_get_post` / `wp_get_post_full` — есть ли пост, title, status, content
- `wp_ability_easy_mcp_polylang_get_post_language` — язык
- `wp_yoast_get_post_seo` — SEO
- `easy-mcp-post-meta/get-fields` — если тул есть: source_urls, social_titles, social_posts

Поста нет — ошибка, не insert.

Правки пиши на диск, в `post.json` тот же `post_id`. Покажи diff (что было на сайте / что станет). Затем кнопки.

Заливка правок — только после кнопки:
- `zip_mcp` / `export_zip` → import-from-zip с тем же `post_id` в json (плагин update, не новый пост)
- `publish_mcp` → `wp_update_post` (content, title, excerpt, featured_media) + `wp_ability_easy_mcp_polylang_set_post_language` + `wp_yoast_update_post_seo` + теги/категории + при наличии `easy-mcp-post-meta/set-fields`
- точечная правка фразы: `wp_replace_in_post`
- точечная мета: `wp_update_post_meta` (не для Yoast — Yoast через `wp_yoast_update_post_seo`)

### Подготовить ZIP (`zip`)

Если пакета нет — сначала «подготовить новость». Картинки и thumbnail **не** перегенерируй: копируй файлы с диска.
Чеклист: есть `images/thumbnail.jpg`; в json поле `thumbnail`; это выбранный концепт, не `image1.jpg`.

Архив: `news/<slug>/<slug>.zip`.
Внутри вложенная папка **slug** (без префикса `news/`):

```
slug/
  post.json
  images/thumbnail.jpg
  images/image1.jpg
  images/image2.jpg
```

Верни путь. В WP не импортируй, пока не сказали залить.

### Экспортировать ZIP / Залить ZIP (`export_zip` / `zip_mcp`) — одно и то же

1. Нет ZIP → `node public-files/index.js pack news/<slug>`.
2. `node public-files/index.js start news/<slug>` → взять `data.zipUrl` (`https://….ngrok…/slug.zip`). Нет `zipUrl` — стоп.
3. MCP `easy-mcp-zip-post-import/import-from-zip` с `zip_url` = `data.zipUrl`. Не `zip_path`. Не бинарник. Не base64.
4. В `finally` всегда `stop`.
5. Успех: `post_id`, edit-ссылка, status. Плагин сам заливает картинки из ZIP и подставляет `[image name="…"]`. Файл thumbnail в ZIP не обязателен: нет файла — featured пропускается, импорт не падает. Есть файл — thumbnail → featured.
6. Падение — честно ошибка. Запасной путь руками: WP Admin → Tools → ZIP Post Import.

### Залить в WordPress, картинки по одной (`publish_mcp`) — без ZIP

1. Языки Polylang + категории/теги.
2. Не `wp_upload_media` (base64) для JPEG сцен/thumbnail.
3. Уже есть чужой публичный HTTPS (сток) → `wp_upload_media_from_url`.
4. Локальные файлы: `start news/<slug>`, каждый `data.files[].url` → `wp_upload_media_from_url` (thumbnail в контент не ставить), в `finally` `stop`.
5. Ngrok URL — только аргумент загрузки. После upload бери `id` + URL с сайта (`source_url` / `media_details.sizes.large.source_url`).
6. В `content` поста каждая сцена — блок Gutenberg (id и `wp-image-ID` = id вложения, `src` = URL медиатеки, size `large`):

```
<!-- wp:image {"id":2503,"sizeSlug":"large","linkDestination":"none"} -->
<figure class="wp-block-image size-large"><img src="https://САЙТ/wp-content/uploads/…/file-1024x576.jpg" alt="ALT" class="wp-image-2503"/><figcaption class="wp-element-caption">Подпись</figcaption></figure>
<!-- /wp:image -->
```

Без `id` / без `wp-image-*` — брак (редактор предлагает перезалить).
На диске и в ZIP по-прежнему `[image name="image1.jpg"]` (не ngrok, не чужой CDN). Gutenberg пишется только в момент MCP-заливки, после ответа медиатеки.
Цитату в WP не оставляй обычным абзацем. Блок quote, текст внутри `<em>` (курсив на сайте):

```
<!-- wp:quote -->
<blockquote class="wp-block-quote"><p><em>Текст цитаты</em></p></blockquote>
<!-- /wp:quote -->
```
7. Thumbnail только `featured_image_id` / `featured_media`, в контент не ставить.
8. Новый пост: `wp_ability_easy_mcp_polylang_create_post_with_language` (`draft`, `featured_image_id`, content с блоками, `source_urls`, `social_titles`, `lead_simhash` если кабинет уже дал 16 hex). Существующий: `wp_update_post` + язык + Yoast + при наличии тула `easy-mcp-post-meta/set-fields`. Нет поста с ID — ошибка.
9. Верни `post_id` и edit-ссылку. Честно: что ушло в WP, что осталось только на диске.

### Тайтл для FB (`fb_title`)

3 варианта **текстом в чате**, не AskQuestion.
Язык статьи, 8–16 слов, одна строка. Эмодзи по смыслу в начале И в конце (формат: эмодзи + пробел + текст + пробел + эмодзи). Внутри текста эмодзи нет. В начале 1–2, в конце 1–2, всего ≤ 4.
Кликбейт без капса всей строки и без политики, если её нет в статье.
Под каждым оригиналом сразу короткий русский дубль.
Все 3 сразу в `social_titles` (`post.json`). Excerpt этими строками не заменяй. WP не трогай, кроме `set-fields`, если есть `post_id` и тул.
После строки тайтла — пустая строка, затем CTA. Если язык статьи `de`, CTA **дословно**, не переводить и не перефразировать, в каждый из 3 вариантов:

```
👇Lest den Artikel und sagt uns, was ihr denkt!? Aber bitte ehrlich!⬇
```

Для других языков CTA не подставляй, пока его нет в этом правиле.

### Поиск по источникам (`find_sources`)

Алиасы: «проверь источники», «есть ли уже эта новость», «найди по ссылкам».
Нет тула `easy-mcp-post-meta/find-by-sources` — скажи, Extra Fields не подключён.
Есть: `{ "urls": ["https://..."] }`. Покажи карточки: title, excerpt, language, source_urls, social_posts, matched_urls, status, post_id. Полный текст не печатай.
Совпадений нет — так и скажи. Новую статью не пиши, пока не подтвердят.
Команда именно «проверь эти ссылки» — покажи совпадения. Команда поиск / «найди и сделай» — см. ниже: совпадение = материал уже использован, **другую** новость.

### Где запощено / не в ФБ (`social_check`)

Алиасы: «уже в фб?», «постил ли я это», «что не запощено в фейсбук», «не выложенные в соцсети».
Тул: `easy-mcp-post-meta/find-by-social`. Нет тула — Extra Fields не подключён.

Есть `post_id` (или контекст поста): `{ "post_id": N, "network": "facebook" }`. Ответ: `posted` true/false, `posted_on` (список сетей), ссылки в `social_posts`. Полный текст не печатай.
Нет id, «что ещё не в ФБ»: `{ "network": "facebook", "posted": false, "limit": 20 }`. По желанию `"language": "de"`. Покажи карточки: title, post_id, language, posted_on, ссылка ФБ если есть.
Уже запощенные в сеть: `"posted": true`.
Другая сеть: `"network": "telegram"`.

После того как человек запостил в ФБ — `set-fields` `{ "post_id": N, "social_posts": { "facebook": "https://…" } }` (остальные сети не затирай).

### Поиск актуальных новостей (`search`)

Кандидаты: оригинал + 1–2 предложения по-русски, ссылка, почему кликбейт для аудитории 50+.
Кнопки: `1. Оригинал — коротко по-русски`.
Если есть `easy-mcp-post-meta/find-by-sources` — **до показа кандидатов** прогони URL каждого кандидата. `count > 0` / есть matched_urls = этот материал уже на сайте. **Не предлагай его.** Ищи другую новость, снова проверь источники. Повторяй, пока не наберёшь свежие (обычно 3–5), которых нет в поле источников. Тул недоступен — ищи как обычно и скажи, что дубли не проверил.
Статью не пиши, пока не выберут пункт или не скажут «делай сразу». После выбора — «подготовить новость», затем кнопки.

### Найди и сделай (`find_make`)

Лучший кликбейтный кандидат 50+. Сначала `find-by-sources` по его ссылкам. Уже использован — молча возьми следующего, снова проверь. Не предлагай дубль и не спрашивай «обновить или новая». Подошёл свежий — кратко назови источник, сразу «подготовить новость». ZIP и WP не трогай.

### Найди и сделай ZIP (`find_zip`)

Как «Найди и сделай», затем сразу «подготовить ZIP» из тех же файлов (thumbnail не перегенерируй). WP не импортируй.

### Найди и залей на сайт (`find_upload`)

Пакет + ZIP + Залить ZIP (`zip_mcp`, ngrok `zip_url`). Нет `post_id` от MCP — не пиши, что пост на сайте.

### Перевести пост (`translate`)

Сделать **новый** пост на другом языке и потом связать. Исходник не переписывай.

Какой пост переводить:
- Человек назвал id («переведи 123», «post_id 123») — бери этот id.
- Id нет — бери пост, о котором шла речь: `post_id` из последнего показа / заливки / `post.json` в чате. Если по смыслу несколько — спроси одним вопросом, не молчи и не бери чужой.
- Нет ни id, ни контекста — спроси id. Не создавай «перевод ниоткуда».

Целевой язык: из фразы («на русский», «en»). Нет языка — спроси.

Перед любой работой **обязательно** `wp_ability_easy_mcp_polylang_get_post_language` по исходному id. Смотри `language` и `translations` `{ "de": 123, "ru": 456 }`.
- Перевод на этот язык уже есть — покажи тот id, edit-ссылку. Новый пост не создавай. Спроси: открыть его / обновить его / всё равно новый.
- Языка в карте нет — можно переводить.

Дальше:
1. Пакет в новой папке `news/<slug-языка>/`, `post_id: 0`, `language` = целевой. Текст переведи. Картинки можно скопировать. Thumbnail — overlay на языке перевода.
2. Залей как новый (`zip_mcp` или `publish_mcp`). Получишь `new_id`.
3. Сразу выполни «связать перевод с постом»: исходный id + `new_id`.
4. Снова `get-post-language` — в `translations` есть новый язык.

### Связать перевод с постом (`link_translation`)

Только склеить **уже существующие** id. Новых постов не создаёт. То же поле Translations в редакторе WP (языки → id поста).

Человек должен указать id (или оба понятны из чата):
- «свяжи 456 с 123» / «привяжи перевод 456 к посту 123»
- один id + «к этому» = второй из контекста
- нет ни одного id и нет контекста — спроси оба. Не угадывай с сайта наугад.

Перед связью **обязательно** проверь оба:
`get-post-language` для каждого id. Смотри `translations`.
- Уже связаны друг с другом на нужных языках — скажи, ничего не трогай.
- У одного уже есть другой пост на том же языке — покажи конфликт, не перезаписывай молча.
- Языки двух постов одинаковые — ошибка, не связывай.

Связь: `easy-mcp-polylang/link-post-translations` / `wp_ability_easy_mcp_polylang_link_post_translations`:

```
{ "translations": { "de": 123, "ru": 456 } }
```

Ключ = язык поста, значение = его post_id. Минимум две пары. В карту положи **все** id из обеих проверок плюс новые: иначе Polylang может отвязать третий язык. Не ставь немецкий id в ключ `ru`.

ZIP `post.json` Translations не пишет. После тула снова `get-post-language` и покажи карту.

---

## 4. Статья (текст и post.json)

Язык = язык запроса / контекста. Аудитория 50+. Живой журнал, не канцелярит.

Структура: сильный заголовок → лид (2–4 абзаца) → подзаголовки → бытовые сцены, диалоги, мнение «соседей/врача/семьи», чем дело кончилось.

### Объём

Тело **строго 3000–4000 слов** (1260–2000 = незавершено, так сдавать нельзя).
`Слов: N` перед показом. N < 3000 — допиши, не спрашивай про заливку.

Реальная история / есть ссылка: сначала выжми источник, потом ищи фон (даты, место, похожие случаи, закон, болезнь). Не останавливайся на пересказе одной ссылки.
Мало фактов — живые сцены и диалоги **вокруг известных фактов**, без новых «реальных» имён.
Вымысел только если сказали БЕЗ (см. ниже) — тогда можно додумывать до объёма.
Не лей воду «в наше время важно».

**Источники в тексте — обязательно для новости.**

Новость = любая задача про события/статью, пока человек явно не сказал БЕЗ.
БЕЗ (тогда блока нет, `source_urls: []`): фразы вроде «без источников», «придумай без ссылок», «вымысел», «фейк», «чистый вымысел». Молчание ≠ БЕЗ.

Два места, оба обязательны для новости (не БЕЗ):

1. **В теле.** У факта, цифры или чужой реплики из СМИ — в том же абзаце короткая кликабельная ссылка: название источника + URL. Не сваливай все ссылки только в конец. Сцены и диалоги, которые додумал, ссылкой не помечай.
2. **В конце `content`** (не в excerpt) тот же набор URL списком. `<h2>` на языке статьи:
- de: Quellen
- ru: Источники
- en: Sources
- иначе то же слово на языке статьи

Дальше `<ul>` на **3–5 пунктов**. Каждый пункт: кликабельная `<a href="…">`, дата, что именно взяли (цифра, цитата, факт). Главные URL дублируй в `post.json` → `source_urls`.
Нет ссылок в абзацах или нет блока `<h2>Quellen`/`Источники`/`Sources` при новости — брак, допиши, не показывай как готовое.
Не выдумывай СМИ и не ставь битые ссылки. Сцены и диалоги в списке источников не «подтверждай» (это домысел вокруг фактов).

Пример хвоста контента:

```
<h2>Quellen</h2>
<ul>
<li><a href="https://example.com/story">Название материала</a> — 15.10.2026, цифры / цитата</li>
<li><a href="https://example.com/other">Другой источник</a> — дата, что взяли</li>
</ul>
```

Имена: даны — настоящие. Вымысел без имени — можно дать. В реальных историях имена не выдумывай.
Водяные знаки и названия источников с картинок убирай.

### HTML на диске

Не сплошной текст:

- лид в `<p>`, дальше `<h2>` каждые 300–500 слов (минимум 5–7)
- абзацы 2–4 предложения
- 2–4 `<strong>` на фразе, не на абзаце
- 1–3 `<em>` (курсив) на короткой фразе, не на абзаце и не вместо `<strong>`
- 1–2 цитаты. Курсив обязателен, иначе в WordPress цитата выглядит обычным текстом:

```
<blockquote><p><em>Текст цитаты</em></p></blockquote>
```
- где уместно короткий `<ul>` (3–5), не списком всю статью
- картинки между разделами, не обе в начале
- на диске / в ZIP: плейсхолдер `[image name="image1.jpg"]`
- в WordPress при `publish_mcp`: только Gutenberg `<!-- wp:image {"id":…} -->` + `<img class="wp-image-ID" src="https://САЙТ/wp-content/uploads/…">`
- нет `<h1>` в контенте, нет пустых `<p><br></p>`

### Пакет на диске

Одна статья = `news/<slug>/post.json` + `news/<slug>/images/`.
Пока нет папки + json + image1 + image2 + thumbnail — подготовка не закончена.
Пока это новость (не БЕЗ) и в `content` нет ссылок в абзацах или нет блока Quellen/Источники/Sources — подготовка тоже не закончена.

Поля `post.json`: `post_id` (0 если новый), `title`, `slug`, `status: draft`, `language`, `excerpt`, `category`, `tags` (5), `yoast_title`, `yoast_description`, `yoast_focus_keyword`, `thumbnail`, `images`, `content`, `source_urls`, `social_titles`, `social_posts`.
`social_posts` — **одно** универсальное поле (объект), не отдельное WP-поле на каждую сеть. Ключ = сеть (`facebook`, `telegram`, `instagram`, `x`, …), значение = публичная ссылка на пост. Пустой ключ / нет ключа = туда ещё не постили. Сейчас достаточно `facebook`. Когда запостили в ФБ: `easy-mcp-post-meta/set-fields` `{ "post_id": N, "social_posts": { "facebook": "https://…" } }` (остальные поля не затирай: если не передаёшь source_urls/social_titles — они остаются). Поиск «уже постил в ФБ?» / «что не в ФБ» = `easy-mcp-post-meta/find-by-social` (см. команду `social_check`). Один пост: `get-fields` тоже показывает `social_posts`.
`category` — основная рубрика. Новость по смыслу: основная = новостная рубрика языка статьи, даже если в `category_names` есть ещё темы. Первой в списке всегда она.
Старое имя одной ссылки `source` отдельно не пиши: главная ссылка — первый элемент массива `source_urls`. Блок Quellen в `content` от этого не отменяется.

Пример:

```
{
  "post_id": 0,
  "title": "Заголовок",
  "slug": "nazvanie-stati-slug",
  "status": "draft",
  "language": "de",
  "excerpt": "Кликбейтный текст для Facebook",
  "category": "Категория",
  "tags": ["tag1", "tag2", "tag3", "tag4", "tag5"],
  "source_urls": ["https://example.com/original-story"],
  "social_titles": [
    "😢 Короткий кликбейтный тайтл один 💔",
    "😱 Короткий кликбейтный тайтл два 🏠",
    "💔 Короткий кликбейтный тайтл три 😢"
  ],
  "social_posts": {},
  "yoast_title": "SEO title",
  "yoast_description": "Meta description",
  "yoast_focus_keyword": "keyword",
  "thumbnail": "thumbnail.jpg",
  "images": "images",
  "content": "<p>Факт с цифрой. Источник: <a href=\"https://example.com/original-story\">Название</a>.</p>\n\n<blockquote><p><em>Текст цитаты курсивом</em></p></blockquote>\n\n[image name=\"image1.jpg\"]\n\n<p>Дальше текст</p>\n\n[image name=\"image2.jpg\"]\n\n<h2>Quellen</h2>\n<ul>\n<li><a href=\"https://example.com/original-story\">Название</a> — 15.10.2026, что взяли</li>\n<li><a href=\"https://example.com/two\">Второй</a> — дата, что взяли</li>\n<li><a href=\"https://example.com/three\">Третий</a> — дата, что взяли</li>\n</ul>\n"
}
```

Thumbnail в контент не ставь. ZIP не пакуй, пока не сказали «подготовить ZIP» / «Найди и сделай ZIP».

## 5. Картинки и thumbnail

Файлы: `news/<slug>/images/` (минимум 2 сцены + `thumbnail.jpg`).

Сцену — только GenerateImage или скачать готовое фото по URL. Не Canvas / Paint / SVG / палочки / детский коллаж. GenerateImage упал — остановись, не рисуй замену.
После генерации руками можно только плашку+текст на thumbnail (способ B). Нож, куклу, лицо, фон не дорисовывай.

Картинка = **сцена абзаца**, не «тема вообще». Перед показом две строки:

```
В тексте: …
На фото: …
```

Не совпадает — не клади в `images/`, генерируй или ищи заново.

### Когда генерировать, когда брать готовое

1. **Вымысел** / «придумай без ссылок» → сцены GenerateImage. Сток «вообще про тему» нельзя. Знаменитостей в кадр не ставь.
2. **Реальная история** → сначала ищи фото, которые уже есть (источник, репортаж, кадр события). Совпадает с абзацем — скачай в `images/`.
3. Реальная, но подходящего фото **нет** → GenerateImage (не случайный сток «про воду», не чужие лица «на тему»).
4. **Простое без сюжета** (пустой двор, фасад, море, документ) → сток / готовый URL ок, если кадр = текст.
5. Люди + действие в вымысле → всегда GenerateImage.
6. Люди + действие в реальной новости → реальное фото героев/события, если есть и узнаваемость уместна; нет — GenerateImage.

Нельзя: файлы из другой статьи; одно фото бассейна/дома на все сцены; подбор «по настроению».

Промпт GenerateImage: кто, сколько людей, возраст (50+ если герои такие), что делают руками, где стоят, свет, одежда, эмоции лиц. Не промпт `pool, photorealistic`.

Публичный HTTPS готового фото храни рядом с материалом (для `wp_upload_media_from_url`). Нет URL — локальный файл + заливка через public-files.

### Thumbnail (обязателен в подготовке)

Кликбейт **1200×630**, текст **в пикселях**. Без крупной белой надписи = брак.
Не сжимать фото под плашку. Не кадр статьи с одной строкой сверху.

Сборка: фон-сцена на весь кадр 1200×630 + 1–2 акцента поверх (кружок / флаг / предмет, чаще справа) + белый жирный текст **на** картинке, в нижней трети, по центру. Текст не под фото и не отдельной подписью ниже кадра, кадр не удлиняется.
Если белый текст на фото плохо читается — под самим блоком текста положи полупрозрачный тёмный фон (плашка поверх пикселей, не под картинкой). Ширина плашки = ширина текста, 60–70%, не на всю ширину кадра. Если текст и так читается, плашку можно не ставить.
Ширина блока текста **максимум 70%** ширины картинки, цель **60–70%**. Уже 60% можно, шире 70% — брак, перегенерируй. Длинный слоган — две короткие центрированные строки внутри этой же полосы.
Круг / шарик с предметом или лицом по смыслу: аккуратная тонкая обводка. Цвет один, по смыслу: белый, красный, синий, зелёный или жёлтый. Не радуга и не толстая каракульная рамка.

Зачем спрашивать концепт: один раз выбрать вариант. Ответ человека = сразу GenerateImage этого варианта и файл `images/thumbnail.jpg` в том же заходе, вместе с текстом и сценами. Второй команды «генерируй тамбнейл» ждать нельзя.

Порядок:

1. Если концепт в этом чате ещё не выбран — три устных варианта кнопками AskQuestion (оригинал overlay — русский дубль — коротко фон/акцент). Несколько картинок сразу не генерируй. Молча один не утверждай. На этом сообщении остановись и жди кнопку.
2. Человек ответил номером / «бери первый» / текстом варианта. В **этом же** ответе вызови GenerateImage и запиши `news/<slug>/images/thumbnail.jpg`. Не пиши «принял», «готовлю», «сейчас сделаю» и не пересказывай факты вместо файла. Такой ответ без jpg = задача не сделана, ход не заканчивай.
3. Уже выбранный концепт не спрашивай снова. «Давай» / «подготовь» после выбора = генерируй обложку сразу, не копируй фото.
4. `thumbnail.jpg` — только сгенерированная обложка: текст на пикселях фото (не под кадром), ширина 60–70% (не больше 70%), акцент из концепта. Если акцент — круг/шарик, обведи его одним цветом по смыслу (белый, красный, синий, зелёный, жёлтый). Способ A (всё в одном GenerateImage) или B (сцена GenerateImage, потом плашка и текст поверх фото).
5. Запрещено сдавать обложку как копию `image1` / стока / «pool-фото» / переименованный кадр статьи. Нет overlay или нет акцента из выбранного концепта — это не thumbnail, перегенерируй до показа пакета. Руками сцену не дорисовывай.
6. Пакет не называй готовым, пока этого файла нет на диске.

Команды ZIP / заливка **не** делают новый thumbnail: пакуют уже сгенерированный файл. Файла нет — сначала GenerateImage выбранного концепта, потом пакуй.

Промпт на английском, точный overlay-текст языка статьи в кавычках:

```
photoreal cinematic Facebook cover 1200x630, text OVERLAID on the photo in the lower third, not a caption strip below the image, do not extend the canvas under the photo, do not look like a child drawing or Paint collage, no stick figures, no squeezed photo, large white bold sans-serif text CENTERED, if the text is hard to read add a semi-transparent dark panel ONLY behind the text block (on top of the photo, same width as the text, not full image width), text block 60 to 70 percent of image width, NEVER wider than 70 percent, NOT full width, generous empty margins left and right, two short centered lines if needed, exact text: "...", circular accent on the right with a thin clean border in one color only (white or red or blue or green or yellow, pick by meaning), [scene], high-end clickbait thumbnail
```

**Язык overlay на пикселях — только язык статьи.** Русский текст на `thumbnail.jpg` запрещён.

После файла в чате всегда:

```
Overlay на thumbnail: "оригинальный текст"
По-русски: "перевод / смысл"
Ширина текста: ~N%   ← цель 60–70, больше 70 нельзя
Акцент: …
Обводка круга: белый / красный / синий / зелёный / жёлтый — или «круга не просили»
```

Если статья уже на русском — строку `По-русски:` не дублируй.

## 6. Порядок работы

1. Полностью подготовь статью на диск (`news/<slug>/`).
2. Покажи всё (пути, заголовок, `Слов: N`, текст со ссылками в абзацах и блоком Quellen/Источники/Sources либо явно «БЕЗ по просьбе», цитаты в `<em>`, картинки, thumbnail, SEO, теги, язык, excerpt, `source_urls`, social_titles).
   Если новость и в тексте нет ссылок в абзацах или нет хвоста Quellen — не переходи к кнопкам, сначала допиши.
3. Спроси следующей командой через **AskQuestion**.
4. ZIP / WP — только после явной кнопки пользователя.

Правки уже залитого поста: `update` → тот же `post_id` → снова ZIP или `publish_mcp`.

## 7. MCP-тулы

Только MCP, без REST (`/wp-json/` не звать). Тул из списка нет в сессии — не падай, скажи какого нет и продолжи чем есть.

### Прочитать (перед обновлением и перед «уже есть на сайте?»)

- `wp_get_post` — пост по id
- `wp_get_post_full` — пост целиком (когда мало полей у get)
- `wp_list_posts` / `wp_search_posts` — найти пост, если id не дали
- `wp_ability_easy_mcp_polylang_get_post_language`
- `wp_yoast_get_post_seo`
- `wp_get_post_meta` — сырая мета, если нужно
- `easy-mcp-post-meta/get-fields` — source_urls + social_titles + social_posts + lead_simhash (тула нет → пропусти)
- `easy-mcp-post-meta/find-by-sources` — `{ "urls": ["https://..."] }`. На search/find_make при count>0 — другая новость.
- `easy-mcp-post-meta/find-by-lead-simhash` — дубль сюжета по lead fingerprint. `{ "lead_simhash": "…" }` или `{ "title": "…", "content": "…" }`. count>0 — сюжет уже на сайте.
- `easy-mcp-post-meta/find-by-social` — был ли пост в сети / список не запощенных. `{ "post_id": N, "network": "facebook" }` или `{ "network": "facebook", "posted": false }`
- `wp_list_categories` / `wp_get_category`
- `wp_list_tags` / `wp_get_tag`
- `wp_list_media` / `wp_get_media`
- `wp_create_preview_link` — превью черновика, если спросили ссылку

### Создать

- `wp_ability_easy_mcp_polylang_list_languages`
- `wp_ability_easy_mcp_polylang_create_post_with_language` — новый пост + язык + категории/теги + Yoast-поля + `source_urls` + `social_titles` + `lead_simhash` (16 hex с кабинета, если есть) + `featured_image_id` (если Extra Fields выключен — extra-поля просто не уедут, пост всё равно создавай)
- `wp_create_post` — только если create_post_with_language нет; сразу следом `set_post_language`

### Обновить уже существующий post_id

- `wp_update_post` — title, content, excerpt, slug, status, featured_media
- `wp_replace_in_post` — точечная замена фразы в контенте
- `wp_ability_easy_mcp_polylang_set_post_language`
- `wp_ability_easy_mcp_polylang_get_post_language` — язык + карта `translations` { "de": 123, "ru": 456 }
- `wp_ability_easy_mcp_polylang_link_post_translations` — связать переводы. Аргумент `{ "translations": { "de": 123, "ru": 456 } }`. Минимум два языка. Это не создаёт пост, только склеивает уже существующие id.
- `wp_yoast_update_post_seo` — title / description / focus keyword
- `wp_add_post_terms` — докинуть теги/категории
- `wp_update_post_meta` — произвольная мета (не `_yoast_wpseo_*`)
- `easy-mcp-post-meta/set-fields` — source_urls / social_titles / social_posts (`{ "facebook": "https://…" }`) / lead_simhash (только если поле ещё пустое)
- `wp_update_post_blocks` / `wp_get_post_blocks` — если правишь Gutenberg-блоки уже залитого поста
- ZIP-обновление того же id: `easy-mcp-zip-post-import/import-from-zip` (`post_id` в json, поста нет → ошибка плагина, не новый insert)

Не создавай новый пост, если задача — обновить.

### Медиа

- `wp_upload_media_from_url` — сток HTTPS или ngrok `data.files[].url`
- `wp_get_media` / `wp_list_media` / `wp_update_media`
- Не `wp_upload_media` (base64) для сцен и thumbnail

### ZIP

- `easy-mcp-zip-post-import/zip-package-spec` — формат пакета, если сомневаешься
- `easy-mcp-zip-post-import/import-from-zip` — только `zip_url` из `node public-files/index.js start news/<slug>` (`data.zipUrl`)

### Запрещено

- REST `/wp-json/`, `wp_rest_write`, `wp_rest_read` вместо тулов выше
- `zip_path` с диска ИИ
- говорить «залито», если тул не вернул `post_id` / `success`
